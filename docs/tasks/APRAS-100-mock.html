APRAS-100 · mock

Contraste abaixo de 4,5:1 deixa de bloquear o salvamento

Hoje a paleta avançada com um par ilegível é recusada: a API responde 422 e o botão Salvar fica desabilitado. Depois desta tarefa a paleta é salva como foi enviada e o par ilegível volta no corpo da resposta, em contrast_warnings, como aviso.

De que cor fica o painel de aviso: âmbar ou o vermelho de hoje?

Abaixo, o mesmo formulário duas vezes, com a mesma paleta ilegível digitada e o Salvar habilitado nos dois. As duas opções têm o mesmo título, as mesmas frases e o mesmo ícone de triângulo: a única diferença é a cor do painel. Em A ele é âmbar — o mesmo tom dos selos de “pendente” do produto. Em B ele continua vermelho, como é hoje.

Compare e responda com uma letra: A ou B. A spec implementa A se nenhuma letra chegar, porque o vermelho é a cor que as pessoas já leem como “bloqueado” e o botão deixou de bloquear; voltar ao vermelho é um commit de uma linha.

O que não está em jogo: a troca das frases de recusa (“não pode ser salva”) por frases de aviso (“pode salvar assim mesmo”) e a troca do ícone de octógono pelo de triângulo acontecem nos dois casos — um painel vermelho dizendo “não pode ser salva” ao lado de um Salvar que funciona não é opção. Por isso os dois cartões abaixo trazem exatamente o mesmo texto e o mesmo ícone.

Sobre o resto deste mock: só o par A/B logo abaixo mostra as duas cores. Daqui para frente o mock pinta A (âmbar) no formulário interativo, na caixa “DEPOIS” do Colar paleta e no rótulo “DEPOIS” do corpo da API. Se a resposta for B, esses três lugares ficam vermelhos (--destructive) com as mesmas frases e o mesmo ícone: só a cor muda.

O formulário, interativo

Troque os valores e veja o painel e o botão reagirem. Um hex malformado (ex.: #GG0000) continua bloqueando o Salvar — só o veredito de contraste deixou de bloquear.

Paleta clara (recorte de 4 dos 13 campos)

invisível na tela real (sr-only) — mostrado aqui só para leitura

↑ este parágrafo é sr-only no produto — a tarefa não acrescenta texto visível nenhum à tela; o painel abaixo já mostra a contagem e os pares, e o parágrafo verde já mostra a frase de “tudo passa”. É a única região aria-live. A frase traz a contagem e o pior índice, então quase toda edição que muda a medição muda o texto anunciado — e um texto igual não é reanunciado. Ela nunca é desmontada, então passar de “falhando” para “tudo passa” também é anunciado. O Salvar aponta para ela com aria-describedby, e os testes a localizam pelo id — não por role="status", que a confirmação de “salvo” já usa nesta mesma seção.

↑ o painel de aviso não é região viva: hoje ele é role="alert", o que equivale a aria-live="assertive", e relia os treze itens da lista a cada tecla. Ele perde o role e passa a ser localizado por data-testid="brand-contrast-warning".

A revisão do “Colar paleta”

O diálogo de colar tem um bloco de recusa próprio, com a frase “Esta paleta não pode ser salva enquanto um par estiver abaixo de 4,5:1”. Ela deixa de ser verdade, então o bloco vira aviso — caso contrário o diálogo contradiz o botão que está a dois dedos dele.

ANTES

Estas cores não podem ser salvas

2 combinação(ões) abaixo do mínimo legível de 4,5:1 (WCAG 2.1 AA, texto normal).

Esta paleta não pode ser salva enquanto um par estiver abaixo de 4,5:1. Desfaça, corrija o texto e aplique de novo, ou feche e ajuste o campo à mão.

DEPOIS

Estas cores são difíceis de ler

2 combinação(ões) abaixo do mínimo legível de 4,5:1 (WCAG 2.1 AA, texto normal).

Esta paleta pode ser salva como está — os pares abaixo de 4,5:1 são um aviso, não um impedimento.

A troca de frases acima acontece nas duas respostas da pergunta. A letra escolhida decide só a cor da caixa “DEPOIS”: em B ela fica vermelha, com estas mesmas frases.

O que a API passa a responder

ANTES — 422, nada é salvo 

PATCH /api/v1/tenant-profile  →  422
{
  "detail": "Estas cores não podem ser
             salvas: 1 combinação(ões)
             abaixo de 4.5:1.",
  "failures": [
    { "pair": "muted-foreground/muted",
      "ratio": 3.93, "minimum": 4.5,
      "scheme": "light" }
  ]
}

DEPOIS — 200, salvo literalmente, com aviso 

PATCH /api/v1/tenant-profile  →  200
{
  "id": "…", "name": "Vista Verde",
  "brand_theme": { "mode": "advanced",
    "light": { "muted": "#e4e8e7",
               "muted-foreground": "#6f746e", … },
    "dark": null },
  "theme": { "light": {…}, "dark": {…} },
  "contrast_warnings": [
    { "pair": "muted-foreground/muted",
      "ratio": 3.93, "minimum": 4.5,
      "scheme": "light" }
  ]
}

contrast_warnings é derivado na leitura, então o GET seguinte traz o mesmo aviso: ao reabrir a tela a pessoa vê de novo o que salvou. É null quando não há brand_theme e [] no modo simples. A rota pública /c/<slug> não ganha o campo.
